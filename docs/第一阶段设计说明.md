# 第一阶段设计说明（外部 Live2D 优先）

## 目标与范围

第一阶段打通“桌宠窗口 → 设置 → 外部模型入口选择 → 只读检查 → 模型级适配元数据 → 安全表演回退”的闭环。白音只作为默认人格与视觉参考，不制作或等待白音专属 PSD、Cubism 工程、分层模型或绑定结果。

同一套人格和关系状态可以绑定任意合法外部模型。外部模型只负责视觉资源、参数和动作文件，不能把模型文件名或参数 ID 反向写入人格逻辑。

## 外部模型入口

用户可以选择：

1. 一个 `.model3.json` 文件；
2. 一个包含唯一 `.model3.json` 的目录。

主进程解析入口的 `FileReferences`，并在同目录检查 `.moc3`、纹理、physics3、CDI3、exp3 和 motion3 文件；同时扫描同目录的额外 `.exp3.json` 与 `.motion3.json`。所有外部资源只读访问，禁止复制、重命名、修改或写入外部目录。

目录含多个入口时要求用户直接选择 `.model3.json`，避免静默选择错误模型。路径不存在、JSON 损坏、资源缺失、越界引用和不可读文件都会转成可见诊断，不执行任何外部脚本或可执行文件。

## 模型级适配

`code/src/shared/live2d.ts` 定义与人格解耦的适配协议：

- CDI3 参数映射到 `head_x`、`eye_open_l`、`mouth_open`、`breath` 等语义参数；
- exp3 参数效果映射到语义表情；
- motion3 文件/组映射到语义动作；
- 未验证的资源回退到 `neutral` 或空效果；
- 参数值按模型适配器的建议范围裁剪，禁止渲染层接受任意 Cubism 参数名；
- `Live2DAdapterConfig` 按模型入口生成，适配数据与模型路径绑定，不进入角色人格包。

当前阶段不内置具体 Cubism runtime，因此 UI 在模型检查通过后仍显示 CSS 安全占位层，并明确标注 runtime 未连接。后续接入 runtime 时应以适配器为唯一入口，保留安全回退和诊断路径。

## 许可与发布边界

导入或切换模型前，用户必须确认已获得该模型及其纹理、表情、动作资源的使用许可。若同目录存在许可说明，程序只读提取署名、商用、二次发布、二改和水印提示；未知条款不会被推断为允许商用。

外部模型路径不进入 `electron-builder` 的 `files` 清单，portable EXE 不包含用户模型。模型运行时状态保存在 Electron 用户数据目录，外部源目录不产生写入。

## IPC 边界

- `state:get`：返回普通设置、默认角色和当前外部模型检查状态，不返回 API Key。
- `live2d:choose-file` / `live2d:choose-directory`：只返回用户选择的路径。
- `live2d:inspect`：主进程只读解析指定入口，返回诊断和适配数据。
- `settings:save`：保存路径和普通设置；新模型路径必须携带许可确认。
- `chat:start` / `chat:event` / `chat:cancel`：与模型资源无关的在线对话通道。

第一阶段没有任意系统命令执行、自动下载模型或修改外部模型目录的能力。
